# 朝暮：待办按项目分组（父组 + 子任务）

日期：2026-09-06
状态：已确认，待实现
承接 `2026-09-05-todo-drag-when-design.md`、`2026-09-06-structured-memory-design.md`（项目机制）

## 要解决的问题

待办越攒越多，其中很多其实是同一件大事拆出来的小项。现在全部平铺在「以后」一栏，没有总览：看不出一件事总共包含几件事、还剩几件、什么时候能做完。

明确**不要**真层级：父任务不是一条可勾选、会卡住列表的待办。每条任务仍是小的、可独立完成、可单独进「今天」的原子项——今天可以从 A 组挑一件小事、从 B 组挑一件小事。「组」只是组织和展示的维度。

## 做法

**组 = 项目（复用现有 `Project`）**。解析层 already 给任务打 `project` 标签、上下文 already 注入项目摘要，这次把项目从幕后标签升级为待办页的分区维度。不新建「分组」实体，不加 `parentId` 树。

### 「今天」栏

平铺不变，不分区。任务行保留项目徽标（`todoMeta` 已有）。勾选、左滑删除、长按拖拽全部照旧。

### 「以后」栏

按组分区，从上到下：

1. **进行中的组**（按 `Project.order` 排，缺失按 `createdAt` 兜底；空组也显示，便于拖入）
2. **未分组**一区（没有 `projectId` 的任务）

**已完成的组不在「以后」显示**——已完成的事不再关心分组。把该组某条已完成任务重新取消勾，组会自动激活回 `active` 并重新出现（见「组的生命周期」）。

组标题行 = 拖拽把手 + 组名 + 进度计数（已完成数/总数，如 3/8；空组不显示）+ 折叠箭头。点标题折叠/展开；折叠状态存设置（Prefs），下次打开保持。

进度计数 = 组内全部任务（含历史已完成）里的完成占比，跨天累积，这样「这摊事推进到哪了」可见。

栏底有「＋ 新建组」入口：输入组名即建出空组，随后可拖任务进去。

### 组的生命周期

- **自动完成**：组内最后一条 open 任务被勾掉时，`project.status` 自动置 `done`，组随即从「以后」消失。不弹确认。
- **自动重激活**：往已完成组里加新任务（聊天确认落入、手动移入或重打开任务）时，`status` 自动回 `active`。
- 手动入口保留：组标题菜单里可重命名、手动完成。不单独提供「重新打开」——往已完成组加新任务即自动重激活。

### 聊天与确认框

解析层不动（`ParsedTask.project` 已存在）。确认框从平铺列表改成按组展示：同组候选收在组名标题下，可整组勾选、也可单条勾；落库时才创建的新组，组名旁标「新」。确认后任务带 `projectId` 落库，照旧走 `App.vue` 的 `onPropose`；**确认框/整理给出的新组名在落库时先建组再挂载**（`App.vue` 的 `resolveProjectId`），不会静默丢进未分组。

「自动整理待办」（`compose-plan.ts`）同样带组：提示词附上现有项目列表，输出 schema 加可选 `project` 字段；落库经 `applyFullPlan` 的 `PlanEntry`（`title` + 可选 `projectId`）写归属，裸标题不动现有归属。

### 拖拽

现有 `applyMove` 扩展为认识组的版本（仍是纯函数，UI 薄封装）：

- **任务在组内上下拖** = 组内排序（重写该组内 `Todo.order`）。
- **任务拖进别的组的分区** = 改 `projectId`，插入落点位置。
- **从「今天」拖到「以后」**：落点在某个组的分区内就进那个组（改归属）；落点在分区外的空白处，回它自己所属的组排末尾；无组的进未分组区。
- **从「以后」拖回「今天」**：照旧只改 `when`，`projectId` 保留（徽标还在，明天拖回去仍认组）。
- **组标题行可拖** = 排组的上下顺序（重写涉及组的 `Project.order`）。
- 未分组区内部同样可拖排序。

手势、抬起观感、边缘自动滚、已完成不可拖等，全部沿用 `2026-09-05-todo-drag-when-design.md` 的约定。

### 手动操作

- 待办页「以后」栏底部「＋ 新建组」：空手建组。
- 任务左滑「分组」：改所属组 / 新建组。
- 组标题菜单：重命名、手动完成。

## 数据

- `Project` 加可选字段 `order`（组排序；缺失按 `createdAt` 兜底，兼容旧数据，**不需要 DB 版本升级**，与既有可选字段同策略）。
- `Todo` 结构不变；`projectId`、`order` 字段沿用，`order` 的排序范围从「桶内」变为「组内」。
- `projectRepo` 增加排序写入（类比 `todoRepo.move`）。
- 自动完成/重激活写成纯函数（放 `todos.ts` 或新小模块），在勾选与落库两处调用。
- 设置增加折叠状态（组 id 列表），存 Capacitor Preferences。

## 不改

「今天」平铺与勾选流程、日记快照（`snapshotLogTitles` 只认标题和 today/later）、`set_today_plan` / `applyTodayPlan` / `applyFullPlan`、上下文注入（`context.ts` 项目摘要照旧）、解析层字段与失败兜底、三页底栏、单机存储、左滑删除。
