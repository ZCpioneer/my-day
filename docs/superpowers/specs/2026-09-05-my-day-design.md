# 朝暮 V0 设计

日期：2026-09-05  
状态：已实现；待办三层见 `2026-09-05-today-later-auto-tidy.md`；自动整理与日记收口见 `2026-09-05-tidy-plan-and-diary-design.md`；确认后清对话见 `2026-09-05-close-session-after-plan-design.md`；自动整理一次重排今天和以后见 `2026-09-05-tidy-today-and-later-design.md`；长按拖动改栏见 `2026-09-05-todo-drag-when-design.md`  
产品名：朝暮（仓库 `my-day`）

面向自己用的「日志 + Todo + 思维整理 Agent」。第一版只做**一天的闭环**：早上立计划，白天随时聊并抽出待办，晚上对照完成情况回顾，留下一篇日记。

## 1. 目标与非目标

### 要验证的事

连续用约两周，看是否：

- 每天只花几分钟，却比自己写日记更完整
- 明显减少「刚才想到又忘了」
- 早上有计划、晚上能对照，而不是又堆出一个新项目

### 第一版必须有

- 手机上独立安装的安卓 App（不依赖电脑常开）
- 对话：朝（开始今天）、暮（回顾今天）、白天续写同一条对话
- 从对话里抽出 Todo，**必须用户确认**才写入
- 待办页打卡（待完成 / 已完成）
- 晚上生成当日日记（计划、做成了、没做完、一段状态）
- 自己的 DeepSeek API Key；自用阶段可内置一把默认 Key，正式发布前删掉
- 屏幕上可见的调试日志，方便对照失败原因

### 第一版不做

桌面小组件、周/月/年看板、独立心理档案、日历、长期目标树、知识图谱、多 Agent、账号与云同步、iOS、应用商店、语音输入、社交、情绪量表、复杂统计。

未勾完的待办会带到下一天早上的开场白，但不做「延期 / 取消 / 项目」等复杂状态。

## 2. 谁在用

只有作者自己。小米安卓手机，侧载 APK。想法多、容易把一个念头升级成新项目。Agent 的职责是帮忙回忆、排优先级、抽出行动，而不是替他开新系统。

## 3. 界面

三个底栏入口：**对话 / 待办 / 日记**。示意见 `demo/index.html`（可点，非真 AI）。

- 顶栏：产品名「朝暮」+ 当天日期。三页都在。
- **朝 / 暮** 两个仪式按钮：只出现在对话页。待办、日记里不出现。
- 对话页：当天一条时间线 + 底部输入。
- 待办页：未完成 / 已完成，点击勾选。不在这里聊天。
- 日记页：当天一篇总结。未生成时说明「晚上点暮之后会出现」。
- 设置：顶栏齿轮，三页都能进。用于 API Key、模型、调试开关。

视觉方向按 demo：夜里手帐（墨底、灯暖金、暮蓝），不要通用紫渐变仪表盘。

## 4. 一天怎么过

一天只有**一条对话**。朝、暮、白天随手说，都写进今天。

### 朝 · 开始今天

用户一点，Agent 先开口（不等人打字）：

1. 问好
2. 报还没做完的事（昨天留下的 + 今天已有的）
3. 问今天怎么安排

用户说计划或新想法。Agent 按截止时间和重要性给一个顺序建议。可以继续聊。听到「要去做的动作」才提议新任务。

### 白天

同一条对话随时续写。纯吐槽、纯想法不弹框。只有判断为可执行任务时才弹出确认。

### 暮 · 回顾今天

用户一点，Agent 先开口：

1. 今天几件事、勾了几件、没动的是哪些
2. 问怎么了

然后给建议、给能立刻变小的改法，也给安慰。可以收束时调用「生成今日日记」，写入日记页。状态由对话推断，用户不用另写。

同一天可再点朝/暮：朝已开过则再对一下计划；暮已有日记则更新今天这一篇，不另开第二天。

### Todo 确认（硬规则）

Agent **永远不直接写入待办**。它最多调用「提议新任务」。界面弹出确认框（可勾选条目）→「确认加入」才写入 →「这次不加」则丢弃。待办勾选只发生在待办页。Agent 没有「帮你勾掉」的工具。

## 5. 架构

手机要完全单机，纯网页做不到：浏览器不能把 Key 直连 DeepSeek（跨域），也没有电脑上的转发可依赖。

```
安卓 APK（Capacitor 壳）
  └── Vue 3 界面（对话 / 待办 / 日记 / 设置）
        ├── 本地存储：聊天、待办、日记、设置
        ├── Agent 循环：上下文 + DeepSeek + 工具
        └── 原生 HTTP：带用户 Key 请求 DeepSeek 云
```

- 界面：Vue 3 + Vite，手机宽度，与 demo 同一信息结构
- 壳：Capacitor，仅安卓。电脑只用于打包；装上后出门不用电脑、不用自建服务器
- 网络：Capacitor 原生 HTTP（或等价原生请求），禁止依赖浏览器 `fetch` 打 `api.deepseek.com`
- 模型：DeepSeek 开放平台，OpenAI 兼容的 Chat Completions + Tool Calls
- 默认模型：`deepseek-v4-flash`（性价比）。设置里可改为 `deepseek-v4-pro`
- 数据：全部在本机。第一版不做登录、不做云同步

打包产物：可侧载的 `.apk`。不上架。

## 6. Agent

不是「系统提示词里自称专家」。第一版是**单 Agent**：

`模型 + 当天真实上下文 + 少量工具 + 有上限的思考-行动循环`

### 每次请求带上的上下文

- 本地日期与时刻
- 当前模式：朝 / 暮 / 闲聊
- 未完成待办列表（含是否跨天留下）
- 今日已完成条数与标题
- 今天的对话（过长则截断早期闲聊，保留朝开场、暮开场、最近若干轮）

### 工具（模型只能请求，代码执行）

| 工具 | 作用 | 副作用 |
| --- | --- | --- |
| `list_todos` | 读当前待办 | 无 |
| `propose_todos` | 提议新任务（标题必填，可带一句理由） | **不写库**；弹出确认框，用户确认后才写入 |
| `suggest_order` | 给今日未完成项一个建议顺序 | 只出现在对话里，不自动排序列表 |
| `write_daily_log` | 按结构写今日日记 | 成功则覆盖「今天」那一篇 |

禁止的工具：标记完成、删除任务、创建项目、改日期。

### 循环

1. 组装上下文，调用 DeepSeek。第一版关闭思考模式（`thinking` 不开启），减少工具回传的复杂度。模型仍用 flash / 可选 pro。
2. 若返回 tool calls：校验参数 → 执行 → 把结果作为 `tool` 消息回传 → 再调模型
3. 一轮用户发言最多 **4** 次模型调用，超出则停下并在对话里说明「这轮没做成，再说一次」
4. `propose_todos`：标题为空、与已有待办标题重复（忽略空白与大小写）的项丢掉；合法项才进确认框
5. 用户点确认/不加之后，把结果回写给模型，让它用一句话收尾，不再偷偷再提议同一批

### 说话原则（写进系统提示）

- 每次少问，连续、自然，不要一次丢一堆问题
- 朝：先报事实（还剩几件），再问计划，再给优先级建议
- 暮：先对照 Todo，再问怎么了；建议 + 可执行的缩小版 + 安慰
- 不要把一个想法升级成新项目；能变成一条 Todo 就变成一条
- 不要声称已经写入待办；只能说「要不要加」

## 7. 数据

按手机本地日历的「今天」分天。

**DayChat**

- `date`：`YYYY-MM-DD`
- `messages[]`：`id, role (user|assistant|system), content, createdAt, mode?`
- 确认框本身不是模型消息；确认结果用一条简短的本地系统备注或下一条 assistant 收尾即可

**Todo**

- `id, title, status (open | done), sourceDate, createdAt, completedAt?, fromMessageId?`
- 跨天：`open` 的条目不过期，早上开场白会带上
- 「待确认」不是库里的稳定状态：只存在于当前确认框。取消即不落库

**DailyLog**

- `date`
- `plan`：早计划（模型归纳）
- `done[]` / `undone[]`：生成时按当时勾选快照
- `state`：一段状态（由对话推断，用户不另写）
- `updatedAt`
- 同一天暮再次生成则覆盖

**Settings**

- `apiKey`：用户粘贴的 Key；若为空则使用内置默认调试 Key
- `model`：默认 `deepseek-v4-flash`
- `debugOverlay`：默认第一版为开

存储：IndexedDB（WebView 内，单库 `zhaomu`）存对话、待办、日记；设置（Key、模型、调试开关）用 Capacitor Preferences。杀进程再开都还在。不要再加一套 SQLite 或本地文件。

## 8. DeepSeek 与 Key

- Base URL：`https://api.deepseek.com`
- 接口：`POST /chat/completions`，第一版**不流式**（整段返回，方便把请求/失败打到屏幕 Debug）。以后再加流式。
- Tool Calls 用官方 OpenAI 兼容格式
- **设置页可编辑 Key**。用户提供的默认调试 Key 写在源码里一处显眼的常量（如 `src/debug/default-key.ts`），文件头注释：`DEBUG ONLY，正式发布前删除`
- 请求顺序：设置里的 Key → 若为空则默认调试 Key → 若仍空则拒绝发送并提示去设置
- 正式发布前必须删除默认 Key，改为强制用户自备
- Key 不打进日志全文（屏幕调试里最多显示前 4 位 + 掩码）

默认 Key 由作者稍后提供，实现时再填入。文档与 git 历史应避免把真 Key 写进本设计文件。

## 9. 屏幕调试日志（第一版必做）

对话页（或全局浮层）有一块可展开的 **Debug** 面板，默认打开。每条日志显示在屏幕上，不要只写 `console.log`。

至少记录：

- 时间
- 事件：`http_start` / `http_ok` / `http_fail` / `tool_call` / `tool_result` / `propose_ui` / `todo_confirmed` / `todo_rejected` / `log_written` / `agent_stop`
- HTTP 状态码、耗时
- 模型名
- 工具名与校验后的参数摘要
- 失败原因原文（截断到合理长度）

不记录完整 API Key。面板可清空、可复制，方便把原因发回来调试。正式发布前可藏到设置里的开关，第一版先常显。

## 10. 出错

| 情况 | 行为 |
| --- | --- |
| 无 Key（设置空且无默认） | 不能发消息；对话区一句中文说明去设置粘贴 |
| 401 / 额度 | 「Key 不对或没有额度」 |
| 无网 / 超时 | 本地 Todo、日记、历史对话可看可打卡；失败那句留在对话里，可重发 |
| 工具参数非法 | 丢掉该项，不当新 Todo |
| 循环超限 | 停止并说明「这轮没做成」 |
| 日记生成失败 | 不覆盖旧篇；可在暮里再请一次 |
| 跨日 | 新对话；`open` 待办保留；朝的开场白带上它们 |

## 11. 验收（真机）

1. 侧载 APK，打开能进三页；无电脑、无自建服务
2. 用默认或设置里的 Key 能聊
3. 朝：报留下的任务，给顺序建议，弹出确认；确认后待办页看得到
4. 待办能勾，已完成分区更新
5. 白天说「还要给房东转水电费」会弹框；说「有点烦」不弹框
6. 暮：对照完成情况，生成日记；日记页能看到计划 / 做成了 / 没做完 / 状态
7. 杀进程再开，数据还在
8. 飞行模式：能看能勾，不能聊，屏幕 Debug 能看到失败原因
9. 朝/暮只在对话页出现

## 12. 实现边界

- 第一版按 1～2 天能装到自己手机上用的标准砍功能，不为「更像人生 OS」加模块
- 周/月/年以后若要做，只消费每日日记的结构，不在 V0 预做页面
- 桌面小组件以后若要做，再在 Capacitor 的 `android/` 里加原生 Widget；V0 不留空实现
