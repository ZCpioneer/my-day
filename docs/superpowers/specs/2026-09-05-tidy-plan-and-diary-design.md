# 朝暮：自动整理只刷新待办，日记自己收口

日期：2026-09-05  
状态：已通过；实现计划见 `docs/superpowers/plans/2026-09-05-tidy-plan-and-diary.md`  
承接 `2026-09-05-today-later-auto-tidy.md` 的待办三层；改掉「自动整理一身兼朝暮」。

## 要解决的问题

自动整理按有没有 `planConfirmedAt` 切换成写日记之后，对话里看不出这段是开始今天还是结束今天。开始一天是看待办，结束一天是看日记。

## 一天怎么走

- **对话**：聊眼前的事。发送左边「自动整理」把当前会话收成今日待办。只动待办，不写日记。一天可点多次，每次都是刷新。
- **待办**：今天 / 以后 / 已完成，只打卡。过夜不改 `when`。只打卡、从不整理的人，今天那几件继续留着。
- **日记**：页底下「整理成日记」写今天这一篇。今天没点的话，下次打开（或 App 开着跨过零点）给昨天补一篇。

不把朝 / 暮按钮加回对话顶。不拆成朝一场、暮一场。底下也不做四颗提示键。

## 写入规则

| 写什么 | 谁触发 | 要不要确认 |
| --- | --- | --- |
| 待办（今日计划 / 记到以后） | 对话里自动整理，或白天 Agent 提议 | 必须弹框，不确认不动库 |
| 今天的日记 | 日记页「整理成日记」 | 点按钮就是同意，不再另弹框 |
| 昨天的日记 | 打开 App / 回到前台 / 开着跨日 | 直接写，不再问 |

Agent 仍不能勾掉任务，不能在对话里直接写库。

## 自动整理

位置不变：`[ 打字 ] [ 自动整理待办 ] [ 发送 ]`，只在对话页。点了等于用户说「请根据本段全部对话，整理并更新今日待办。」。确认今日计划后清空当前气泡（旧对话进 `archive`，日记仍能读到），见 `2026-09-05-close-session-after-plan-design.md`。

它做且只做：

1. 看当前会话和三层待办
2. 建议今天做哪几件
3. 用 `set_today_plan` 弹出「今天做这几件？」
4. 没选上的今天事项掉回以后；新冒出来、今天不做的用 `propose_todos` 记到以后
5. 提醒有没有漏的

不调用写日记。已经确认过计划再点，仍是刷新今日待办，不是改去写日记。

确认后写入 `planConfirmedAt`。这个字段只表示今天确认过计划，**不再用来切换自动整理的模式**。

白天普通发送：可执行任务仍用 `propose_todos` 记到以后。用户明说「改成今天做这些」才 `set_today_plan`。

## 日记

四段结构不变：早计划、做成了、没做完、状态。做成了 / 没做完只对照「今天」分区，以后不算没做完。勾没勾以待办为准，模型不得把没勾的写成已完成。

### 日记页按钮

文案：「整理成日记」。点了就为**今天**生成并覆盖今天这一篇。生成中按钮不可再点。失败则留在原状，可再点。

这篇写进日记页，用户立刻能看到。不往对话里插气泡。

### 隔夜补写

触发（每次都检查，不靠系统后台）：

- App 冷启动
- 从后台回到前台
- App 开着时本地日历日变了（沿用现有的跨日检查，并加一轮定时：开着时约每分钟看一次日期）

补哪一天：从昨天往前最多 14 天，在「有痕迹、还没有日记、早于今天」的日期里取**最近的一天**，只写这一篇。更早的缺篇不补。完全没打开过、当天没有任何痕迹的日子不补。

有痕迹：那天的对话有消息或有 `planConfirmedAt`，或有待办的 `completedAt` 落在那天。

补写用触发时那一帧的待办快照，不因随后的自动整理改已经写入的那一篇。打开或跨日时**先发起补写**（不要等用户先点自动整理），但不挡第一屏：补写在后台跑，失败不影响对话 / 待办。

没 Key、请求失败：跳过，下次打开再试。已有日记的日子不覆盖。

日记页仍只展示今天。补的那一篇在 IndexedDB 里，当前页看不到。刚补上时可以有一句「已补上上次的日记」，不是弹框，也不跳转。

## 生成日记（不是对话回合）

独立函数 `composeDailyLog(date)`，不走对话里的 `runAgent`，不往 `DayChat` 追加消息。

- `done` / `undone`：对该 `date` 做 `partitionTodos`（与现在 `write_daily_log` 同一套），不让模型编造勾选。
- `plan` / `state`：模型根据那天的对话和快照来写。那天没确认过计划，`plan` 写明没有确认过，可补一句从对话里看到的安排。
- 直接 `logRepo.put`。日记页按钮和隔夜补写都走这里。

对话用的工具列表拿掉 `write_daily_log`。自动整理或白天聊天若仍提起写日记，只口头说去日记页，不写库、不弹确认。

## 数据与界面

待办三层、`Todo.when`、过夜不改 `when`，与上一份 spec 相同。

`DayChat.planConfirmedAt` 保留，确认今日计划时写入；新的一天没有这个字段。

`ChatMode` 的 `evening` 不再被自动整理使用。自动整理按整理待办来提示（不再分「还没计划 = 朝 / 已有计划 = 暮」）。设置里的朝暮分界仍可给普通对话一点时间感，不驱动任何按钮。

空状态：

- 对话：想到什么直接说。聊完点发送左边的「自动整理」，刷新今天的待办。
- 待办今天区：还没定今天做哪几件。（去对话里自动整理）
- 日记：点下面「整理成日记」。今天不整的话，明天打开会补上昨天。

## 不改

三页底栏、待办只打卡、日记四段、设置里的 Key / 模型 / 朝暮分界、单机安卓、一天一条对话。

## 测试要覆盖

- 自动整理走 `set_today_plan` 确认框；不写日记。
- 已有 `planConfirmedAt` 再点自动整理，仍刷新待办，不写日记。
- 不确认，待办不动。
- 日记页按钮写入今天，无确认框，对话无新消息。
- 隔夜：昨天有痕迹、无日记 → 写入昨天；有日记 → 不覆盖。
- 隔夜：昨天无痕迹、更早一天有痕迹无日记 → 只补那更早最近的一篇。
- 隔夜不改任何待办的 `when`。
- 无 Key / 请求失败：界面能用，日记维持原状。
